## Ch 0. Hook — 왜 우리에게 생성형 AI가 필요한가

**핵심 메시지:** 품질/수율 데이터를 들여다보는 시간의 대부분은 "정리·집계·엑셀 작업"에
새어나간다 — AI는 그 반복 작업의 시간을 줄여, 원인 파악·의사결정에 쓸 시간을 늘려준다.

- 슬라이드: 품질 데이터를 들여다보는 하루, 시간이 어디로 새는가 (엑셀 정리/집계/그래프/보고서 비중)
- 슬라이드: AI 도입 전후 — 같은 결과, 다른 소요 시간

## Ch 1. AI, 제대로 짚고 갑니다 (신규)

**핵심 메시지:** 데이터 분석 이야기로 바로 들어가기 전에, AI/LLM이 근본적으로 무엇을 하는
도구인지부터 짚는다 — 생성형 AI를 처음 접하는 청중을 위한 온보딩. (원본 `index.html`의
알파고→LLM 설명 흐름을 데이터 분석 청중용으로 축약, 바이브 코딩 관련 내용은 제외)

- 슬라이드: 알파고 이야기 — 데이터(수십만 판 기보) + 학습(통계) = "승률 높은 다음 수를
  추천하는 기계"
- 슬라이드: 다른 AI도 같은 로직 — 자율주행/알파고/챗봇, 전부 "다음 확률 분포를 그리는" 방식
- 슬라이드: 그럼 챗봇은? — "다음에 올 말을 예측하는 확률 계산기"
- 슬라이드: 지능형 도서관 비유 — 방대한 글에서 가장 그럴듯한 다음 조각을 찾아주는 존재.
  `index.html` 13pg와 동일한 word-chip 확률 애니메이션 포팅 ("이번 달 불량률, 왜 올랐지?"
  원인 후보들이 확률과 함께 깜빡이다 가장 그럴듯한 답이 정착·발광)
- 슬라이드: 그래서 완벽하지 않다 — 확률적 추정이라 자신 있게 틀릴 수 있음 (Ch4 예고) +
  데이터 분석으로 전환하는 브릿지

## Ch 2. 탐색적 데이터 분석(EDA) 보조

**핵심 메시지:** AI에게 데이터를 "보여주고 물어보는" 것만으로 요약·패턴·이상치 탐지의 초안을
빠르게 얻을 수 있다 — 단, 무엇을 물어봐야 하는지는 분석가가 설계해야 한다.

- 슬라이드: EDA란 무엇을 하는 단계인가 (짧은 리마인드)
- 슬라이드: AI에게 데이터 요약을 맡기는 프롬프트 예시 (컬럼 설명/분포/결측치)
- 슬라이드: 패턴·이상치 탐색 프롬프트 예시 (chat bubble 대화 형식)
- 슬라이드: 좋은 질문 vs 애매한 질문 — 결과 품질이 갈리는 지점

## Ch 3. 코드 생성 — 몰라도 시켜서 쓴다

**핵심 메시지:** pandas/SQL 문법을 몰라도 된다 — "이런 데이터로 이런 걸 보고 싶다"고 말하면
AI가 코드를 쓴다. 분석가(청중)의 역할은 코드를 읽는 게 아니라 **결과가 상식적으로 맞는지
확인하는 것.**

- 슬라이드: 코드를 몰라도 되는 이유 — "엑셀에서 하던 걸 말로 시킨다"는 비유로 문턱 낮추기
- 슬라이드: 예시 1 — 불량 데이터 요약 요청 (자연어 질문 → AI가 표/코드 생성 → 결과, chat bubble)
- 슬라이드: 예시 2 — "이 두 라인의 수율을 비교해서 그래프로 보여줘" (자연어 → 시각화 결과)
- 슬라이드: 같은 요청, 다른 업무 — `index.html` 20pg 패턴(타임라인) 차용. 야간조 불량 확인/
  낯선 설비 로그/신규 장비 데이터/협력사 엑셀 등 4가지 "낯선 데이터를 처음 마주하는" 순간이
  전부 "뭐가 들어있는지 설명해주고 이상해 보이는 값 있으면 짚어줘"라는 토씨 하나 안 바뀐,
  **실제로 통할 법한** 요청으로 해결됨을 보여줌 (최초안의 "요약해서 보여줘"는 그래프 생성 등
  서로 다른 결과물을 기대하기엔 논리 비약이 있어 폐기)
- 슬라이드: 결과 검증 감각 — 코드를 읽지 못해도 확인 가능한 것들 (합계가 맞는지, 상식과
  어긋나는 숫자는 없는지, 데이터 개수가 원본과 같은지)

## Ch 4. AI 분석 결과의 한계와 검증

**핵심 메시지:** AI는 그럴듯한 틀린 답을 자신 있게 내놓는다 — 통계적 해석, 인과관계 추론에서
특히 취약하다. 분석가의 역할은 결과를 그대로 쓰는 게 아니라 교차검증하는 것.

- 슬라이드: 환각(hallucination) 실제 사례 — 없는 컬럼/틀린 통계치를 만들어내는 패턴
- 슬라이드: 상관관계를 인과관계로 착각하게 만드는 AI 답변 사례 (품질/불량률 데이터 예시)
- 슬라이드: 교차검증 습관 — 직접 숫자 재계산, 샘플 데이터로 재현, 출처 요구
- 슬라이드: "AI 결과를 믿어도 되는 상황 vs 반드시 재검증해야 하는 상황" 체크리스트
- 슬라이드: (신규) 그래서, 여러분이 유리합니다 — AI 도구 사용법은 며칠이면 늘지만, 현장을
  아는 눈은 수년이 걸려야 생김. 시니어(도메인 전문가) 청중을 위한 동기부여 슬라이드, Ch4의
  "결과 검증은 결국 사람 몫" 메시지를 그대로 이어받아 "그래서 여러분이 적임자"로 전환

## Ch 5. 도구 비교 — 성격별로 나눠보기

**핵심 메시지:** 도구 이름을 다 외울 필요는 없다 — 대화형/코드·자동화/문서·리서치, 성격만
알아두면 상황에 맞게 고를 수 있다.

- 슬라이드: 생성형 AI 도구, 성격별로 나눠보면 (3개 카테고리 지도)
- 슬라이드: 💬 대화형 어시스턴트 — ChatGPT / Claude / Gemini (오늘 바로 쓸 수 있는 도구)
- 슬라이드: 🤖 코드·자동화 에이전트 — Claude Code / Codex / Antigravity (존재만 알아두기,
  청중이 당장 손댈 도구는 아님)
- 슬라이드: 📚 문서·리서치 보조 — NotebookLM / Claude Projects (자주 참고하는 매뉴얼·기준
  문서를 쌓아두고 재활용, 공유·협업 기능 아님)
