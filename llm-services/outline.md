# LLM 서비스, 업무의 무기로 — 스토리라인

이 문서는 `llm-services/index.html`의 콘텐츠 소스입니다. 챕터/슬라이드를 실제 HTML로 만들기
전에, 여기서 먼저 구성·순서·분량을 확정합니다. 각 챕터는 "핵심 메시지" 한두 문장 + 슬라이드
목록(요지만)으로 구성됩니다.

상태: **HTML 1차 반영 (23장)** — 아래 챕터 구조대로 `index.html`에 실제 슬라이드가
만들어졌습니다. 목차/줄번호는 [slides-outline.md](slides-outline.md) 참고.

## 강의 개요 (확정)

- **제목:** LLM 서비스, 업무의 무기로 — ChatGPT · Claude · Gemini 사내 활용 가이드
- **시간:** 약 45분
- **슬라이드 수:** 23장 (데이터 분석 강의가 60분/29장이므로 유사한 페이스)
- **대상 청중:** LLM 서비스를 처음 접하는 비즈니스 시니어. 업무 예시는 **일반 사무 업무
  기본 + 품질/제조 예시 한두 개 혼합**. 도구 사용법을 디테일하게 가르치는 자리가 아니라,
  기능·종류의 예시를 보여주고 "출발점"을 잡아주는 강의. 완전한 활용법은 다음 고급 강의에서.
- **도입 환경:** ChatGPT Enterprise / Claude Enterprise / Gemini Enterprise **세 서비스 모두
  사내 도입 완료** 가정 → "입력 데이터 학습 미사용, 사내 계정, 보안 검토 완료" 등 Enterprise
  공통 보안 메시지 포함. 단, 사내 보안 등급 규정은 별도 적용됨을 명시.
- **활용 단계 구성:** 3단계로 압축 — ① 대화 활용(프롬프트 엔지니어링) ② 나만의 도구
  만들기(챗봇 설계 + 바이브 코딩·바이브 디자인) ③ 에이전트에게 맡기기(에이전틱 엔지니어링).
  5개 세부 카테고리(프롬프트 엔지니어링/챗봇 설계/바이브 코딩/바이브 디자인/에이전틱
  엔지니어링)는 3단계 안에 배치.
- **강의 관계:** 데이터 분석 강의(`data-analysis/`)와 **독립적인 완결형 강의**.
  AI 기본 개념은 이 덱 안에서 짧게 자체 소개.
- **포맷:** `data-analysis/index.html`과 동일 — self-contained reveal.js, 다크/라이트 모드
  토글, 목차 드롭다운, 전체화면 버튼, Pretendard/JetBrains Mono 인라인 폰트.

## Ch 0. Hook — 도구의 세대교체 (3장)

**핵심 메시지:** 계산기→엑셀→검색엔진→LLM. 우리는 이런 도구 교체를 몇 번 겪었고, 먼저 익힌
사람의 10년이 달랐다. LLM이 대체하는 것은 '판단'이 아니라 '초안을 만드는 시간'이다.

- 슬라이드 1: 타이틀 — SEMINAR · 2026 · LLM AT WORK
- 슬라이드 2: 도구의 세대교체 타임라인 — 수기 장부→스프레드시트, 종이 문서→워드프로세서,
  도서관→검색엔진, 그리고 지금 LLM. "엑셀을 먼저 배운 사람과 나중에 배운 사람" (시니어 공감)
- 슬라이드 3: 하루 업무 지도 — 이메일·회의록·자료조사·보고서 초안·데이터 1차 정리(품질 예시)
  중 LLM이 거들 수 있는 영역. 판단·결정·책임은 사람 몫으로 남음

## Ch 1. LLM, 뭐가 다른가 (3장)

**핵심 메시지:** 지금까지의 도구는 사람이 도구의 '기능'을 배워서 맞춰야 했다. LLM은 처음으로
'말귀를 알아듣는' 도구다 — 단, 확률로 답을 만들어내기에 그럴듯하게 틀릴 수 있다.

- 슬라이드 4: 기존 도구와 비교 — 검색엔진(찾기만)·번역기(한 기능만)·엑셀 매크로(정해진
  반복만) vs LLM. 공통점: 도구에 사람이 맞춰야 했다
- 슬라이드 5: LLM만의 특징 4가지 — ① 자연어가 곧 사용법 ② 맥락을 이어감(대화)
  ③ 결과물을 생성(초안) ④ 한 도구로 범용 + 뒷면: 확률 기반이라 그럴듯하게 틀림(Ch6 예고)
- 슬라이드 6: 비유 "모든 분야 상식을 갖춘 신입사원" — 뭐든 초안은 빠르게, 그러나 회사
  사정은 알려줘야 하고 결과 검토는 상사(여러분) 몫. 이 비유를 Ch5 모델 선택까지 재사용

## Ch 2. 사내에 도입된 세 서비스 (2장)

**핵심 메시지:** Enterprise 계정의 의미(입력 데이터 학습 미사용, 보안 검토 완료)를 알면
업무 문서를 안심하고 쓸 수 있다. 세 서비스는 성격만 다를 뿐 하나만 골라 시작해도 된다.

- 슬라이드 7: Enterprise 공통점 — 개인 무료 계정 vs 사내 Enterprise 계정 비교.
  "업무 문서를 넣어도 되는 이유" + 사내 보안 등급 규정은 그대로 적용됨을 주의
- 슬라이드 8: 성격 비교 카드 — ChatGPT(가장 대중적·범용·이미지) / Claude(긴 문서·한국어
  글쓰기·코드) / Gemini(검색·최신 정보·Workspace 연동). "다 외울 필요 없음"

## Ch 3. 어떤 업무가 얼마나 바뀌나 (1장)

**핵심 메시지:** 0→1 초안은 AI가, 1→100 완성과 책임은 사람이. 업무별 기대 효율을 숫자로.

- 슬라이드 9: 업무별 Before/After 표 — 자료 조사·요약(반나절→30분), 보고서 초안(2시간→20분),
  회의록 정리(1시간→10분), 외국어 메일(30분→5분), 품질 데이터 1차 집계(2시간→20분)

## Ch 4. 활용 3단계 로드맵 (6장, 핵심 챕터)

**핵심 메시지:** 대화(오늘 시작) → 제작(이번 달 목표) → 위임(존재만 알아두기). 단계마다
대표 제품이 있고, 출발점만 알면 나머지는 필요할 때 배우면 된다.

- 슬라이드 10: 3단계 지도 — STEP 1 대화하기 / STEP 2 나만의 도구 만들기 / STEP 3 통째로
  맡기기. 단계별 대표 제품 미리보기
- 슬라이드 11: STEP 1 · 프롬프트 엔지니어링 — 좋은 지시의 4요소(역할·맥락·요구·형식),
  나쁜 예 vs 좋은 예 chat bubble, 파일 첨부·웹 검색 등 기능 존재 소개
- 슬라이드 12: STEP 2a · 챗봇 설계 — 매번 같은 설명을 봇으로 저장: Custom GPT(ChatGPT) /
  Projects(Claude) / Gems(Gemini). 예: 주간보고 양식 봇, 사내 기준문서 Q&A 봇
- 슬라이드 13: STEP 2b · 바이브 코딩 & 바이브 디자인 — "이런 게 있으면 좋겠다"를 말하면
  동작하는 결과물: Artifacts(Claude) / Canvas(ChatGPT·Gemini). 예: 단위 환산 계산기,
  대시보드 시안. "이 슬라이드도 바이브 코딩으로 만들었습니다"
- 슬라이드 14: STEP 3 · 에이전틱 엔지니어링 — 계획→실행→검토→보고를 스스로 도는 에이전트:
  Deep Research(3사 공통), Claude Code / Codex(코드 작업), 에이전트 모드. "존재만 알아두기"
- 슬라이드 15: 한 페이지 지도 — 단계 × 대표 도구 × 대체 업무 × 기대 효과 요약

## Ch 5. 실무 꿀팁 — 잘 쓰는 사람들의 습관 (5장)

**핵심 메시지:** 완벽한 첫 프롬프트는 없다 — 부족한 정보를 더해가며 수렴시키는 회복탄력성이
실력이다. 프롬프트 작성 자체도, 일의 배분(모델·생각 시간)도 AI에게/비유로 풀 수 있다.

- 슬라이드 16: 완벽한 첫 프롬프트는 없다 — 시킨다→본다→보강한다→다시 시킨다 수렴 루프.
  "부하직원에게 일 맡길 때도 한 번에 안 된다"(시니어의 위임 경험과 연결). 실패가 아니라 과정
- 슬라이드 17: 메타 프롬프트 — "내 요청을 더 좋은 프롬프트로 업그레이드해줘. 필요하면 내게
  질문해." AI가 빠진 맥락을 되물어 프롬프트를 완성 — 메타인지 보조. 저장하면 나만의 스킬
- 슬라이드 18: 인기 스킬 활용 — 스킬 = 작업 요령을 담은 지시문 패키지. 대표 예 grill-me
  (기획을 혹독하게 파고드는 질문 공세 리허설). 종류: 글쓰기 코치·회의 준비·아이디어 검증·
  보고서 첨삭. 찾는 법: 서비스 내 스토어/스킬 검색, 커뮤니티 모음, 사내 공유 채널
- 슬라이드 19: 모델 단계적 선택 — 위임 비유: 빠른 모델(즉답형 주니어) / 표준 모델(에이스
  대리, 기본값) / 최고 성능 모델(베테랑 전문가, 느리지만 깊음). 일 크기에 맞게
- 슬라이드 20: Effort(생각 시간) 선택 — "지금 바로 답 줘" vs "내일까지 검토해서 와".
  즉답 모드 vs 깊은 사고 모드(추론). 상황별 추천 조합(메일=빠름+즉답, 원인 분석=고성능+깊음)

## Ch 6. 주의사항 + 마무리 (3장)

**핵심 메시지:** AI는 그럴듯하게 틀린다 — 검증은 사람 몫이고, 그래서 도메인을 아는 시니어가
가장 유리하다. 내일 아침 바로 시작할 수 있는 첫 프롬프트를 들려 보낸다.

- 슬라이드 21: 그럴듯하게 틀립니다 — 환각 주의(숫자·출처·규정은 확인). "도구 사용법은 한 달,
  결과의 진위를 아는 눈은 수년" — 시니어 동기부여
- 슬라이드 22: 오늘의 한 페이지 요약 + 내일 아침 첫 프롬프트 3가지(메일 다듬기, 회의록 요약,
  메타 프롬프트)
- 슬라이드 23: Q&A + 다음 고급 강의 예고(단계별 심화: 프롬프트 실전, 봇 만들기 실습,
  에이전트 활용)
