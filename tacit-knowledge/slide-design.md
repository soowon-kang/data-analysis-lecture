# A. Design Principle (5개)

## 원칙 1 — 화면은 주장하고, 강사는 설명한다

화면에 들어가는 것은 **주장 · 숫자 · 관계** 셋뿐이다. 연구 조건, 표본 크기, 예외, 한계, 사례 전개는 전부 강사 몫이다.
> 적용: 40장 중 **표본 크기를 화면에 넣은 슬라이드는 4장뿐**(S3·S13·S16·S35). 그 넷은 숫자의 신뢰도가 곧 메시지인 경우다.

## 원칙 2 — 제목이 곧 문장이다. 목차가 아니다

"암묵지란?", "LLM의 특징" 같은 제목은 이 덱에 하나도 없다. **모든 제목은 주어와 서술어가 있는 주장**이다.
검증 기준: **§B의 제목만 이어 읽었을 때 강의가 성립해야 한다.** 성립하지 않으면 제목이 아니라 논리가 잘못된 것이다.

## 원칙 3 — 숫자는 문장이 아니라 숫자로 보여준다

"AI 사용 시 소요 시간이 증가하는 경향이 관찰되었다" ❌ → **`+19%`** ⭕
이 덱의 기억 앵커는 여섯 개다: **19% · 80%/12% · +40%/−23% · 51.8%/17.1% · 16% · 4,439명**
> 나머지 숫자는 전부 강사 대사나 각주로 내렸다. 앵커가 일곱 개를 넘으면 하나도 안 남는다.

**⚠️ 검수에서 추가된 규칙**: 화면에 **Primary 위계로 올라가는 숫자는 원 논문 또는 발행기관 원문에서 직접 확인된 것만** 사용한다. 2차 요약(검색 결과·기사·블로그) 경유 수치는 화면에 올리지 않는다.
> **잔여 항목 없음.** S02(한국은행)는 검수 후 원 보고서를 대조해 확인을 마쳤다 — BOK 이슈노트 제2025-22호 「AI의 빠른 확산과 생산성 효과」(2025-08-18)에서 **51.8% · 3.8% · 1.0%**를 직접 확인했고, **17.1% / 미국 26.5%**는 같은 보고서의 세부 수치로 복수 매체에 일관되게 보도된 값이다.
> ⚠️ **화면에 올리지 않는 잔여 수치 1건**: S09 BACKUP의 `145.3 vs 138.6` · `5.6 vs 8.6` · *p*값은 **유료 저널 본문 미대조 상태**다. 화면에는 애초에 올라가지 않으므로 이 규칙에 저촉되지 않으나, **강사가 Q&A에서 이 수치를 입 밖에 내려면 원문을 먼저 확인해야 한다.** 확인 전에는 *"통계적으로 유의한 차이가 없었다"*까지만 말한다.

## 원칙 4 — 사람 이름보다 현상을 먼저 보여준다

화면 상단은 **"숙련자는 선택지를 비교하지 않는다"**, 하단 각주는 작게 **"Klein, RPD"**.
Polanyi·Nonaka·Szulanski 모두 동일하게 처리했다. **연구자 이름이 제목에 오는 슬라이드는 0장이다.**

## 원칙 5 — 해석은 해석으로 표시한다

이 덱에는 강한 명제가 여럿 있지만 그중 일부는 **연구 결과가 아니라 이 강의의 해석**이다(예: "전문가는 덜 본다", L1/L2/L3 3층, 학습 루프).
- 화면에는 **[Evidence] 슬라이드에만 출처를 붙인다**
- **[Interpretation] 슬라이드에는 출처를 붙이지 않는다** — 해석에 논문 각주를 달면 사실처럼 보인다
- 각 슬라이드 명세의 `evidence` 필드에 이 구분을 명시했다

**⚠️ 검수에서 추가된 절차** — `[Evidence]` 태그를 붙이기 전 세 가지를 확인한다.
> ① 원문에서 직접 확인했는가 ② **통계적으로 유의한 결과인가** ③ 저자의 결론과 **같은 방향**인가
> 셋 중 하나라도 아니면 **[Interpretation]으로 강등**한다. (S09가 이 절차의 ②③에서 걸려 수정되었다)

## Framework 슬라이드 설계 원칙 (§15 적용)

세 개 모두 **분류표가 아니라 판단도구**로 설계했다. 검증 기준은 하나다.
> **"수강생이 이 화면을 보고 자기 업무를 얹어볼 수 있는가?"**

# J. Final HTML Content Schema

## 스키마 계약

```yaml
slide:
  slide_id:      string        # S01~S40. teaching-script.md와 동일 번호 (불변)
  section_index: integer       # HTML <section> 순번 1~39 (S31-32가 하나)
  chapter:       enum          # OPENING | CH1 | CH2 | CH3 | CH4 | CLOSING
  slide_type:    enum          # title|question|statement|comparison|evidence|
                               # diagram|framework|case|activity|transition|summary|closing
  density:       enum          # LOW | MEDIUM | HIGH
  title:         string        # 주장문. 목차형 제목 금지
  subtitle:      string?       # divider에만 사용
  core_message:  string        # 한 문장
  visible_content: block       # 화면에 나가는 것만. §C가 단일 원본
  visual_concept: string       # 관계·구조. CSS/배치 지시 금지
  build_steps:   integer       # 1 = 단일, 2 = 2단 빌드
  evidence:      string?       # [Evidence] | [Interpretation] | [Theory] | [Provocation]
  source_id:     string[]      # RB-nn | RS-nn. 비어 있으면 화면 각주도 없음
  speaker_note:  string        # 화면에 나가지 않음
  transition:    string        # 다음 장 연결 문장
```

## 필드 규칙 3가지

1. **`source_id`가 비어 있으면 화면에 각주를 넣지 않는다.** 해석에 출처를 붙이면 사실처럼 보인다 (원칙 5)
2. **`visible_content`의 단일 원본은 §C다.** 이 표에 다시 옮겨 적으면 두 곳이 갈라진다 — 아래 표는 **인덱스**이지 사본이 아니다
3. **`visual_concept`에 CSS·배치·색상을 쓰지 않는다** (`design-prompt` §21). "왼쪽에 두고" 같은 지시가 들어가면 템플릿과 충돌한다
